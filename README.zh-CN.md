# Lumen Code（光码）

用"屏幕 → 相机"高效传输文件。发送端把文件播放成一串彩色格子动画，接收端用相机拍摄并还原文件。不需要网络、不需要配对、没有回传通道。

[English](README.md) · [协议规范（中文）](PROTOCOL.zh-CN.md) · [Protocol (English, STE)](PROTOCOL.md) · [测试向量](test/vectors/test-vectors.json) · [Rust 库](src/rust/README.md)

## 为什么不直接用动态二维码？

动态二维码容易实现，但很慢：一帧 QR v25 只能装约 1.2 KB，而且方形会浪费手机和显示器的大部分屏幕。Lumen Code 保留"相机对准屏幕"的简单，同时大幅提高吞吐量：

| | 动态二维码（v25，常见） | Lumen Code v1 |
|---|---|---|
| 每格比特 | 1 | 2（C4，默认）或 3（C8） |
| 形状 | 正方形 | 跟随屏幕（宽高比最高 1.78） |
| 格子大小 | 由版本决定 | 按屏幕物理尺寸自动选择 |
| 每帧数据（手机屏） | 约 1.2 KB | 约 2.2 KB（C4）/ 3.4 KB（C8） |
| 每帧数据（13 寸笔记本） | 约 1.2 KB | 约 7.2 KB（C4）/ 11 KB（C8） |
| 丢帧 | 通常循环重放 | 喷泉码：每帧都是新数据 |
| 一个角被反光挡住 | 整帧失败 | 用其余三个角继续解码 |

默认每秒 12 帧时，笔记本屏幕的原始容量约 85–130 KB/s。实际速度取决于接收端相机，接收页面会实时显示各项数据。

## 试用

```sh
npm run serve          # http://localhost:8080，直接运行源码（localhost 下可用相机）
npm run serve:https    # https://<局域网IP>:8443，供手机使用（自签名证书）
npm run build          # 生成 dist/，可直接部署的静态站点（用 npm run serve:dist 检查）
```

在发送端屏幕打开 `send.html` 并选择文件，在接收端手机打开 `recv.html`。两个页面都同时支持手机和电脑，无需安装，数据不离开设备。

- **发送端**：可发送文件，也可直接输入或粘贴文本（文件 | 文本 两个标签）；密度（低 / 自动 / 高 / 极高）、4 色或 8 色、纠错等级、帧率、引擎；轻点画面可显示/隐藏控制栏。
- **接收端**：收到的文本直接显示，可一键复制（链接还可直接打开）；文件可保存或打开。进度、速度、格子在相机中的像素大小、成功率，以及一行诊断信息（引擎耗时、相机帧率、识别次数、新帧数、漏帧率），并给出"降低发送端帧率"等提示。
- **引擎切换**：两个页面都可以在 JavaScript 实现与编译成 WebAssembly 的 Rust 实现之间切换（`JS | WASM`），两者生成的帧逐位一致。

## 原理简述

1. 文件可选用 DEFLATE 压缩，再切分成源块；
2. 类 Raptor 喷泉码把每个源块变成无限的符号流，任意约 K+2 个符号即可恢复 K 个符号的源块；
3. 每个符号加上 CRC 成为数据包，再编码为 Reed–Solomon 码字；
4. 码字沿 Hilbert 曲线排进网格，每个码字占一块紧凑区域（相机拍到撕裂帧时只丢少量码字）；
5. 三个定位图案、一个角标、校准点阵和四份帧头，让接收端在透视、镜头畸变、模糊和摩尔纹下仍能定位网格。

完整的规范性描述见 [PROTOCOL.zh-CN.md](PROTOCOL.zh-CN.md)。

## 测试

```sh
npm test                 # 核心（RS、喷泉码）、数据包/源块、经相机模型的端到端、JS<->WASM 互通
npm run test:robustness  # 透视、旋转、镜像、模糊、光晕、摩尔纹、运动模糊、曝光
cd src/rust && cargo test   # 测试向量、Rust 闭环、解码 JS 模拟的相机帧
```

相机模拟器（`test/camera.js`）模拟透视、桶形畸变、光学模糊、颜色串扰、白平衡、暗角、光晕、摩尔纹、运动模糊、4:2:0 色度下采样和噪声。在随机的"手持、没对准"测试中，4 色模式约 30 帧解出 27 帧、码字成功率 84–86%；剩余失败的帧是每格只有约 3 个相机像素并且严重模糊的情况。

## 性能（Apple M2，1080p 相机帧）

| 识别引擎 | 手机尺寸的码 | 笔记本尺寸的码 |
|---|---|---|
| JavaScript（V8） | 14–16 ms | 41–45 ms |
| Rust → WebAssembly | 9–10 ms | 21 ms |
| Rust 原生 | 7–9 ms | 16 ms |

接收端还会跳过已解出的帧（只读帧头，JS 约 8 ms），并把识别频率控制在发送端帧率的约 2 倍，避免手机发热。
