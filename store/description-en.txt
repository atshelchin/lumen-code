Lumen Code sends a file from one screen to a camera. The sender shows the file as a sequence of colour-coded frames; the receiver films them and rebuilds the file. It is one-way: no network, no pairing, no account, no return channel.

GETTING STARTED
1. On the device with the file, tap Send and choose a file or type text.
2. On the other device, tap Receive and keep the whole code in the camera view.
3. At 100 % the file has been checked; open, save or share it.

HOW IT WORKS
- Frames: a grid sized to the physical screen, 2 bits per cell (4 colours) or 3 (8 colours). Any three of the four corners locate a frame.
- Error correction: Reed–Solomon on every codeword (10–30 % parity), CRC-16 on every packet, size and CRC-32 on the whole file. A file that fails the check is never delivered.
- Fountain code: missed or blurred frames and any order are fine. A block decodes from slightly more symbols than it holds (on average 1.6 extra for blocks of up to 1000 symbols).

PERFORMANCE
On a 13-inch laptop screen a frame carries 6.9 KB with 4 colours: 82 KB/s of raw capacity at 12 frames a second. The best end-to-end result so far is 96 KB/s between two phones running the app. What you get depends on the camera; the receive screen shows the live rate.

LIMITS
- Not encrypted: anyone who can see the screen can read the file. Encrypt it first if that matters.
- The checks catch accidental errors, not tampering.
- Tens of KB/s: suited to documents, keys, configuration and photos. Files up to 256 MiB.
- The code flashes up to 60 times a second. People sensitive to flashing light should not look at it; the app asks you to confirm this before the first code plays.

PRIVACY
The app makes no network connections and collects no data.

WORKS WITH
The same app on other phones, the desktop app, and the free web version at lumencode.link. The protocol (version 1.0, frozen) and all the code are open source under the MIT License: https://github.com/atshelchin/lumen-code
